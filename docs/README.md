# Лендинг TrexGo — состояние проекта

Статический сайт продукта: ЭТрН/ЭПЛ, тарифы, форма заявки, блог.
HTML/CSS/JS без фреймворка и сборки.

## Адреса

| Адрес | Что это |
|---|---|
| `trexgo.ru` | **боевой сайт**, хостинг Макхост |
| `trexgo.app` | старый адрес на Vercel — режется ТСПУ, судьба не решена |
| `lk.trexgo.ru` | личный кабинет, планируется, отдельный репозиторий `trexgo-lk` |

## Как обновляется сайт

```
1. Ветка под задачу     git switch -c site-menu-perevozchiki
2. Правки, отправка     git push -u origin site-menu-perevozchiki
                        → превью собралось само, ссылку кинуть на согласование
3. Посмотрели вдвоём    https://trexgo.ru/preview/site-menu-perevozchiki/
4. Слили в main         боевой сайт обновился сам за ~30 секунд
5. Удалили ветку        превью убралось само
```

Push в `main` запускает [.github/workflows/deploy.yml](../.github/workflows/deploy.yml) —
GitHub Actions заливает файлы на хостинг по FTP. Вручную ничего запускать не нужно.

Есть ручной запуск с галкой «холостой прогон»: Actions → Выкладка сайта на хостинг →
Run workflow. Показывает, что изменилось бы, ничего не трогая.

**Репозиторий — источник правды.** Чего в нём нет, то с сервера удаляется.
Правки прямо на хостинге через FTP затрутся при следующей выкладке.

Не заливаются: `.github/`, `CLAUDE.md`, `README.md`, `docs/`, `config-snapshots/`,
`temp/`, служебные файлы.

## Локальный просмотр

Правки смотрим у себя, **до** пуша. Сайт статический, без сборки — достаточно
файлового сервера из папки `site/`:

```bash
python -m http.server 8000
```

Дальше `http://127.0.0.1:8000/`. Правим файл → `Ctrl+F5` в браузере → видим результат.
Остановить — `Ctrl+C`.

Альтернатива без команд: расширение **Live Server** в VS Code — правая кнопка по
`index.html` → Open with Live Server. Само перезагружает страницу при сохранении.

**Открывать `index.html` двойным кликом не годится.** Через `file://` не работает
Метрика, иначе ведут себя относительные пути и часть правил безопасности браузера.
Расхождение видно не всегда — тем оно и опасно.

**Что локально не проверяется:**

- `.htaccess` — локальный сервер не Apache, редиректы и блокировки не отработают;
- всё из списка «чего превью не показывает» (`../rules/preview.md`);
- поведение боевого домена: кэш, сертификат, ТСПУ.

Локальный сервер и превью не заменяют друг друга: первый — для себя в процессе
работы, второе — чтобы показать второму участнику.

## Превью веток

Push в любую ветку **кроме** `main` собирает копию сайта по адресу:

```
https://trexgo.ru/preview/<имя-ветки>/
```

Ссылка появляется в отчёте о сборке: Actions → нужный запуск → Summary.
Открывается с телефона, ничего устанавливать не надо. Внутри превью работает
вся навигация — ссылки в HTML относительные и не уводят на боевой сайт.

Превью **не влияет на боевой сайт**: выкладка `main` ведёт список своих файлов
и посторонние папки не трогает (проверено, детали в
[config-snapshots/mchost.md](../config-snapshots/mchost.md)).

Закрыто от поисковиков двумя способами сразу: `Disallow: /preview/` в `robots.txt`
и заголовок `X-Robots-Tag: noindex` внутри папки. Второй важнее — он работает,
даже если робот пришёл по прямой ссылке из переписки.

**Удаление.** Ветку удалили → превью убралось само
([preview-cleanup.yml](../.github/workflows/preview-cleanup.yml)).
Если ветка ещё нужна, а превью уже нет: Actions → «Убрать превью удалённой ветки»
→ Run workflow → вписать имя ветки.

Косые черты в имени ветки (`site/fix-menu`) превращаются в дефисы: папка будет
`site-fix-menu`. Имя обрезается до 40 символов.

Почему папка, а не поддомен `test.trexgo.ru` — в
[archive/proposals/preview-varianty.md](archive/proposals/preview-varianty.md).

## Почему уехали с Vercel

ТСПУ режет клиентские домены Vercel: соединение устанавливается, заголовки приходят,
а тело обрывается на ~21 КБ и висит до таймаута. Проверено на посторонних сайтах —
`resend.com`, `cal.com`, `linear.app` ведут себя так же. Собственные домены Vercel
(`vercel.com`, `nextjs.org`) при этом работают.

Смена IP внутри Vercel не помогает — фильтр следует за именем домена, а не за адресом.

На Макхосте та же картинка 1,09 МБ приходит целиком за 0,5 с.

## Текущие решения

| Решение | Дата | Суть |
|---|---|---|
| Переезд на Макхост | 30.07.2026 | Vercel режется ТСПУ |
| Деплой через GitHub Actions по FTP | 30.07.2026 | шифрования хостинг не поддерживает |
| Репозиторий публичный | 29.07.2026 | Vercel Hobby не умел приватные репозитории организации |
| `.htaccess` в синтаксисе Apache 2.2+2.4 | 31.07.2026 | версия сервера неизвестна |
| phpinfo убран из `httpdocs` | 31.07.2026 | отдавал наружу пути, IP, имя пользователя |
| Превью веток в `/preview/`, не на поддомене | 31.07.2026 | сертификат не покрывает поддомены |
| Раздел меню «Кому подходит» | 31.07.2026 | вторая ось навигации — по ролям участников перевозки |

## Структура сайта: две оси навигации

Продуктовая ось — что мы делаем: ЭТрН, путевые листы, AI-аналитика. Ролевая ось —
кому это нужно: раздел меню **«Кому подходит»**, выпадающий список без своей
страницы-хаба.

Разрез по ролям взят тот же, что в базе знаний (`knowledge/wiki/etrn/users/`) —
чтобы вики и сайт не разъезжались. Сейчас в разделе три страницы, новая роль
добавляется как ещё один пункт списка.

**В бургере выпадающего списка нет** — все пункты идут одним плоским рядом, ролевые
страницы вперемешку с продуктовыми. На узкой колонке заголовок «Кому подходит» ничего
не группировал, а ломал ряд лишним кеглем и отступом. Раскрывать там нечего, поэтому
кнопка-переключатель на этой ширине просто скрыта.

**Ролевые страницы пока не в `sitemap.xml`.** У `gruzootpravitelyam.html` и
`gruzopoluchatelyam.html` стоит `<meta name="robots" content="noindex, follow">`.
Ставился он, пока это были заглушки; сейчас страницы наполнены, но `noindex` снимается
и запись в `sitemap.xml` добавляется **после того, как тексты посмотрел второй** —
это решение вдвоём, как и вся структура сайта (`../rules/workflow.md`).

Это осознанное отступление от правила «новая страница = навигация + футер + sitemap»
(`../rules/code.md`). Цель правила — чтобы страница не осталась сиротой, как было с
`perevozchiki.html`; здесь она достигается ссылками в меню и футере.

### Общие стили и скрипты ролевых лендингов

Три страницы раздела свёрстаны одинаково — общая шапка сайта, плавающее меню по
странице, hero с макетом телефона, карточки, чёрный блок дедлайна, мобильная плашка
с кнопкой. Общее вынесено в два файла в корне, а не продублировано трижды:

| Файл | Что внутри |
|---|---|
| `role-landing.css` | все классы `.pv-*`: плавающее меню, hero, анимации телефона, секции, адаптив |
| `role-landing.js` | счётчик дней до 01.09.2026, плавающее меню со скроллспаем, мобильная плашка, появление секций |

Подключаются только на этих трёх страницах, после `styles.css` и `script.js`
соответственно. Базовая типографика, кнопки, футер и FAQ живут в `styles.css`
и здесь не дублируются.

Каждый блок в `role-landing.js` сначала проверяет, есть ли его элементы на странице:
состав секций у лендингов разный. Анимация появления секций (`.pv-reveal`) прячет блок
только вместе с классом `js-reveal` на `<html>` — его ставит сам скрипт, так что без JS
секции видны сразу, а не остаются скрытыми навсегда.

### Две навигации на ролевых лендингах

Шапка у ролевых страниц **та же самая, что на остальном сайте** (`nav.nav` из `styles.css`) —
со своей шапкой они оставались единственными страницами без бургер-меню в адаптиве.
Навигация по разделам самой страницы вынесена в отдельный элемент `.pv-pagenav` —
таблетку, которая висит под шапкой:

- появляется, когда прокручен первый экран, и уходит на форме заявки — пока герой
  на виду, второй ряд меню только спорит с шапкой;
- активный раздел подсвечивается, под ним едет чёрный маркер; позицию и ширину маркера
  считает JS — CSS не умеет измерить ширину произвольной подписи;
- активным считается **последний раздел, чей верх прошёл линию в трети экрана**. Считаем
  по `scroll`, а не через `IntersectionObserver`: короткие разделы помещаются в экран
  вместе с соседями, и наблюдатель на них мигает между двумя пунктами;
- на мобильном таблетка тянется во всю ширину и скроллится горизонтально, активный пункт
  подтягивается в видимую часть; кнопка заявки в ней скрыта — внизу уже есть плашка.

Отсюда требование к подписям: **один пункт — одно-два слова**. Ряд из четырёх пунктов плюс
кнопка — потолок, при котором таблетка на десктопе помещается без прокрутки.

Плавный переход по якорю сдвигается на 160 px вместо обычных 80 (`script.js`): под шапкой
висит таблетка, и без запаса заголовок раздела уезжает под неё. Отличаются страницы
наличием `#pageNav`.

## Что настроено в .htaccess

Редирект HTTP → HTTPS, `www` → без `www`, сжатие, кэш картинок на год,
`/favicon.ico` → `favicon.svg`, блокировка файлов, начинающихся с точки
(кроме `/.well-known/` — он нужен для продления сертификата).

## Проверка, что всё работает

```bash
# Страницы (пока DNS не везде доехал — через прямой IP)
curl -s --compressed -m 20 -o /dev/null --resolve "trexgo.ru:443:178.208.83.20" \
  -w "%{http_code} %{size_download}\n" https://trexgo.ru/

# Тяжёлая картинка — главный тест на ТСПУ, должна прийти целиком
curl -s --compressed -m 40 -o /dev/null --resolve "trexgo.ru:443:178.208.83.20" \
  -w "got=%{size_download} time=%{time_total}\n" https://trexgo.ru/Stati_image/5.png

# Превью ветки: должно отдавать 200 и заголовок noindex
curl -sI -m 20 https://trexgo.ru/preview/ИМЯ-ВЕТКИ/ | grep -i "http/\|x-robots"

# Статус выкладок
gh run list --limit 5

# Логи сервера
curl -s --ftp-pasv "ftp://ЛОГИН:ПАРОЛЬ@a250227.ftp.mchost.ru/logs/access_log"

# То же по SFTP — пароль не идёт открытым текстом
curl -s --hostpubsha256 "rtV6fnGKM/gwusoVZa5nKDnNO9f9e5lTqCuoyh6UC/o=" \
  -u "ЛОГИН:ПАРОЛЬ" "sftp://a250227.ftp.mchost.ru/logs/access_log"
```

## Известные проблемы

**Форма заявки ничего не отправляет.** Обработчик в `script.js` прячет форму и
показывает «Заявка принята» — без `fetch`, без `action`. Контакты посетителей теряются.

**Картинки не пережаты** — 7,91 МБ в 15 файлах, самая тяжёлая 2,25 МБ.
На хостинге грузятся быстро, но на мобильном интернете это много. Есть imagick.

**`canonical` в `perevozchiki.html` указывает на `/perevozchiki` без `.html`**, а страница
отдаётся только по `/perevozchiki.html` — адрес без расширения возвращает 404. Либо править
`canonical`, либо заводить ЧПУ в `.htaccess` для всех страниц сразу. Не решено.

**Пароли засветились** в переписке в Telegram: FTP и база. Сменить после того,
как всё устоится, новые — в GitHub Secrets.

**Выкладка идёт по FTP без шифрования** — пароль ходит открытым текстом при
каждом деплое. При этом **SFTP на хостинге работает** (порт 22, OpenSSH 8.7,
те же доступы) — упирается в `FTP-Deploy-Action`, который умеет только FTP.
Варианты: заменить action на SFTP-совместимый (потеряем инкрементальную
заливку — будет выкладываться весь сайт целиком) или оставить как есть и
просто сменить пароль. Пока не решено.

**В `privacy.html` абсолютная ссылка** `href="/privacy.html"` — единственная
в проекте. Из превью она уводит на боевой сайт. Заменить на относительную.
