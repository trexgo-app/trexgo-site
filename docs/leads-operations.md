# База заявок: эксплуатация

Серверный контур формы: PHP 8.0, MySQL `a250227_trexgo`, приватный конфиг вне
`httpdocs`. Этот файл — инструкция по развёртыванию и обслуживанию. Секретов здесь нет.

## Что лежит в репозитории

| Путь | Назначение |
|---|---|
| `api/leads.php` | `POST /api/leads`, приём заявки или подписки |
| `api/config.example.php` | форма приватного конфига без значений секретов |
| `db/migrations/` | пронумерованные миграции MySQL |
| `ops/migrate.php` | применение ещё не выполненных миграций |
| `ops/export_csv.php` | экспорт `leads` или `subscriptions` в приватную папку |
| `ops/backup_db.php` | сжатый `mysqldump` в приватную папку |
| `ops/cleanup_rate_limit.php` | удаление старых окон rate limit |
| `ops/sync_yandex_disk.php` | синхронизация MySQL ↔ `Заявки TrexGo.xlsx` |

Каталоги `db/`, `ops/`, `tests/` и внутренности `api/` закрыты собственными
`.htaccess`, в том числе в превью. Снаружи доступен только обработчик формы.

## Первый запуск

1. Сменить засвеченный пароль базы в панели Макхоста. Финальное подтверждение смены
   пароля делает владелец аккаунта.
2. Скопировать `api/config.example.php` в
   `/home/httpd/vhosts/trexgo.ru/private/leads-config.php`, заполнить значения и
   выставить права `0600`.
3. Сгенерировать отдельный ключ rate limit:

   ```bash
   php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"
   ```

4. Применить `db/migrations/001_create_leads.sql` через phpMyAdmin или один раз
   выполнить `ops/migrate.php` выбранным в панели PHP 8.0 CLI.
5. Проверить, что таблицы и соединение используют `utf8mb4`, а серверная сессия — UTC.
6. Отправить тестовую заявку. После проверки MySQL и обоих уведомлений подключить
   клиентские формы к относительному `api/leads`: так превью не пишет в боевую базу.

Настоящий конфиг не копируется в `httpdocs`, GitHub Secrets или репозиторий.

## Контракт API

Запрос — JSON, только с того же сайта. Обязательны:

- `request_id` — UUID v4, сохраняется для повторной отправки;
- `form_kind` — `lead` или `subscription`;
- `form_started_at` — Unix time начала заполнения, в секундах или миллисекундах;
- `phone` для заявки; телефон или `email` для подписки;
- пустое поле `website` — honeypot, пользователь его не видит.

Дополнительно принимаются имя, email, компания, комментарий, страница, referrer,
источник, UTM-поля и `yclid`. Телефон нормализуется до международного формата. Время
в MySQL хранится в UTC. Повторный `request_id` возвращает тот же `id` без новой строки
и без повторного уведомления.

Успех записи в MySQL возвращает `200`. Если база недоступна, но Telegram или письмо
приняли полные данные, возвращается `202`. Если не сработало ни одно хранилище,
возвращается `503` с телефоном и ссылкой WhatsApp. Телефон, email и комментарий в
технические логи не пишутся.

## Уведомления

В приватном конфиге задаются токен Telegram-бота, отрицательный `chat_id` группы,
адрес получателя и `From`. API всегда пытается отправить оба канала. Ошибка уведомлений
не превращает уже сохранённую в MySQL заявку в ошибку для посетителя.

## CSV и резервные копии

Команды не печатают строки заявок в терминал; результат создаётся с правами `0600`
в каталогах из приватного конфига.

```bash
php ops/export_csv.php --table=leads
php ops/export_csv.php --table=subscriptions
php ops/backup_db.php
php ops/cleanup_rate_limit.php
```

Рекомендуемое расписание в панели Макхоста:

| Команда | Расписание |
|---|---|
| `sync_yandex_disk.php` | каждые 15 минут |
| `export_csv.php --table=leads` | ежедневно |
| `export_csv.php --table=subscriptions` | ежедневно |
| `backup_db.php` | ежедневно |
| `cleanup_rate_limit.php` | ежедневно |

Путь к PHP CLI и `mysqldump` проверить на сервере до сохранения cron. Восстановление
из свежего дампа проверять раз в квартал на отдельной тестовой базе.

## Таблица на Яндекс Диске

Файл — `Заявки TrexGo.xlsx`, один лист. Заголовок нельзя переименовывать или
переставлять. Даты в файле показываются по Москве, при записи в MySQL переводятся в UTC.

Скрипт сохраняет порядок существующих строк. Строка без `id` считается ручной заявкой,
получает UUID и добавляется в MySQL с `source = manual`, если источник не указан.
Удаление строки не удаляет заявку: на следующем прогоне она вернётся в конец. Для вывода
из работы используются статусы `lost` и `archived`.

Перед загрузкой скрипт повторно проверяет `modified`. Если файл менялся во время
прогона, новая версия не загружается, а в Telegram и почту уходит сообщение о конфликте.
Одновременный второй запуск блокируется файловой блокировкой.

## Проверки после развёртывания

- настоящий ли `REMOTE_ADDR` приходит за nginx;
- повтор одного `request_id` не создаёт вторую строку;
- UTM и `yclid` доходят без изменений;
- при недоступной базе заявка приходит в Telegram или по почте;
- в `error_log` нет телефона, email и комментария;
- ручная строка и изменение статуса проходят цикл XLSX → MySQL;
- конфликт `modified` отменяет загрузку и даёт уведомление;
- закрытые URL `/db/`, `/ops/`, `/tests/`, `/api/lib/` отвечают `403`.
