# Как показывать правки до боевой выкладки — разобранные варианты

Дата: 31.07.2026. Выбрана папка `/preview/` на боевом хостинге.
Как это работает сейчас — в [docs/README.md](../../README.md).

Задача: сделать ветку с правкой, дать ссылку второму участнику, получить «ок»,
только потом слить в `main`. На Vercel это было из коробки, после переезда пропало.

## Отклонено: Cloudflare Pages / Netlify

Настоящие превью на каждый pull request, бесплатно, как было в Vercel.

Отклонено потому, что мы только что уехали с иностранного хостинга из-за ТСПУ.
Netlify на 31.07.2026 ещё проходит (измерено: 400 КБ отдаёт целиком), но гарантий
на завтра нет. Ссылка, которая может перестать открываться у смотрящего из России, —
плохой канал для согласования.

К вопросу можно вернуться, если превью понадобятся вне России.

## Отложено: поддомен `test.trexgo.ru`

Технически чище: отдельный корень, боевой сайт не затрагивается вообще,
поддомен закрывается от поисковиков целиком.

Отложено, потому что текущий сертификат Let's Encrypt покрывает только
`trexgo.ru` и `www.trexgo.ru`, wildcard не выпущен. Пока на поддомен не выпущен
свой сертификат, браузер показывает предупреждение о несовпадении имени —
для ссылки, которую отправляешь человеку на согласование, это неприемлемо.

Порядок, если возвращаться: завести поддомен в панели → выпустить сертификат →
поменять `server-dir` в `preview.yml` на `subdomains/test/httpdocs/` →
убрать `Disallow: /preview/` из `robots.txt`.

DNS-зона обслуживается хостером (`ns1..ns4.mchost.ru`), так что поддомен заводится
в панели без похода к регистратору. Отдельного FTP-логина у поддомена не будет —
доступ через тот же аккаунт по пути `subdomains/<имя>/httpdocs`.

## Что проверялось перед выбором

**Не снесёт ли боевая выкладка папку превью.** Опасение обоснованное: в
`deploy.yml` написано «репозиторий — источник правды, чего нет в нём, то удаляется».

Проверено экспериментом: на сервер положена посторонняя папка `zz-probe/`,
запущен dry-run выкладки — `Making changes to 0 files/folders`, папка цела.
`FTP-Deploy-Action` ведёт список **своих** файлов в `.ftp-deploy-sync-state.json`
и чужого не трогает. Папка после проверки удалена.

**Не сломается ли сайт в подпапке.** Ссылки в HTML относительные, кроме одной
абсолютной в `privacy.html` (`href="/privacy.html"`) — из превью она уводит на
боевой сайт. Мелочь, но при правке приватности учитывать.
