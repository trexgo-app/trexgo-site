# CLAUDE.md

Указания для Claude Code при работе с этим репозиторием.

## Что это за репозиторий

Лендинг TrexGo (https://trexgo.ru) — статический сайт из HTML/CSS/JS, без фреймворка и сборки.
Продукт: личный кабинет для выпуска электронных транспортных накладных (ЭТрН/ЭПЛ) с передачей
в ГИС ЭПД через партнёра — Платформу ОФД.

Весь контент — на русском языке.

**Здесь только лендинг.** Личный кабинет — отдельный репозиторий `trexgo-lk`. Не смешивать:
код кабинета, работа с API Платформы ОФД, база данных сюда не попадают никогда.

Текущее состояние проекта, адреса, проверки — [docs/README.md](docs/README.md).
Конфигурация хостинга — [config-snapshots/mchost.md](config-snapshots/mchost.md).

## Соседний репозиторий с базой знаний

На диске эта папка лежит внутри рабочей папки `ЭТрН/` рядом с `knowledge/` — **приватным**
репозиторием базы знаний. Там: вики по рынку ЭПД, разбор конкурентов, продуктовая стратегия,
черновики текстов лендинга (`knowledge/Landing/`) и материалы для контента
(`knowledge/sources/content/`).

Если нужен факт про ЭТрН, ЭПЛ, титулы или регулирование — он там, не выдумывать.
Если правишь тексты сайта — сначала прочитать `knowledge/Landing/sources-and-approach.md`:
в нём записано, что сознательно **не** вынесено на лендинг и почему.

Репозитории независимы: коммит сюда не попадает в базу знаний и наоборот.
Ссылки вида `../knowledge/...` работают в редакторе, но не на GitHub — в тексты сайта их
не вставлять.

**Движение фактов одностороннее: из базы знаний в сайт.** Ничего приватного —
стратегии, гипотез, рисков, разбора конкурентов — здесь оказаться не должно.

## Правила работы

- Правки только в ветке, никогда напрямую в `main`. Ветка называется по смыслу задачи:
  `site-new-pricing`, `site-blog-etrn`, не `fix2`. **Имя ветки становится адресом превью**,
  так что оно должно быть читаемым для человека, которому кинут ссылку.
- Одна задача — одна ветка — один pull request. Не копить разнородные правки в одной ветке.
- Push в ветку собирает превью на `https://trexgo.ru/preview/<ветка>/`. Ссылку давать на
  согласование, не описывать правки словами.
- Деплой не запускать вручную и не заливать файлы по FTP. Push в `main` — и GitHub Actions
  выложит сайт сам.
- Секреты в код не вписывать. **Репозиторий публичный** — ни паролей, ни ключей, ни токенов
  здесь быть не может. Доступы живут в GitHub Secrets.

## Gotchas

- **Репозиторий — источник правды.** Выкладка удаляет с сервера всё, чего нет в репозитории.
  Правки напрямую по FTP затрутся при следующем push.
- **Версия Apache неизвестна**, хостер её скрывает. В `.htaccess` писать только синтаксис,
  работающий и на 2.2, и на 2.4: `RewriteRule ... [F,L]`, не `Require all denied`.
- **Путь `/.well-known/` не блокировать** — через него Let's Encrypt продлевает сертификат.
- **PHP работает как FastCGI** — его настройки через `.htaccess` не меняются, только
  панель или `.user.ini`.
- **Кодировка базы по умолчанию cp1251.** Таблицы создавать явно в `utf8mb4`,
  иначе кириллица и эмодзи побьются.
- **Сертификат без wildcard** — поддомены не покрыты.
- Форма заявки сейчас ничего не отправляет — не считать её рабочей.
- **Ссылки в HTML только относительные** (`privacy.html`, не `/privacy.html`) — иначе
  из превью они уводят на боевой сайт.
- **`/preview/` — служебная папка на сервере**, её нет в репозитории. Не добавлять в
  `sitemap.xml`, не ссылаться с боевых страниц.

## Тон и содержание

Аудитория — перевозчики, логисты, грузоотправители: люди занятые и практичные.

- Пишем по делу, без маркетингового шума и восклицаний.
- Не обещаем того, чего продукт не делает. Не выдумываем цифры, отзывы, клиентов и метрики —
  если нужен факт, спрашиваем у владельца.
- Термины отрасли (ЭТрН, ЭПЛ, ГИС ЭПД, титул, УКЭП) употребляем корректно, при первом
  упоминании расшифровываем.

## Структура

Страницы лежат плоско в корне: `index.html`, `waybills.html`, `perevozchiki.html`,
`blog.html`, `article-etrn.html`, `ai-analytics.html`, `privacy.html`. Картинки — в папках рядом.

При добавлении новой страницы — прописать ссылку в навигации и в футере на остальных
страницах, добавить в `sitemap.xml`.

## Чего не делать

- Не переписывать сайт на фреймворк без явной просьбы.
- Не добавлять зависимости и сборку ради мелкой правки.
- Не менять юридические тексты (политика конфиденциальности, оферта, реквизиты) по своей
  инициативе — только по прямому указанию.
- Не трогать домен и настройки DNS.

## Правила поддержки документации

**Один факт — одно место.** Если IP, версия или правило встречается в двух файлах — это баг.
Проверка: «если я удалю эту строку, агент сделает что-то не так?» Если нет — удалить.

| Данные | Куда |
|---|---|
| Текущее состояние, адреса, проверки | `docs/README.md` |
| Конфигурация хостинга | `config-snapshots/mchost.md` — read-only, снимать заново |
| Заметные вехи и решения | `docs/archive/CHANGELOG.md` |
| Отклонённые варианты и почему | `docs/archive/proposals/` |
| Старая диагностика | `docs/archive/diagnostics/` |
| Построчная история | git log |
| Правила для агента, gotchas | этот файл |
| Пароли и доступы | GitHub Secrets и память Claude, **никогда не в репозиторий** |

Всё неактуальное — в `docs/archive/`, одной папкой. Не заводить `old/`, `backup/`, `legacy/`.

В `docs/README.md` не писать «раньше было так, но потом...» — либо удалить, либо перенести
в архив с датой. README отвечает на вопрос «как сейчас», а не «как дошли до жизни такой».
